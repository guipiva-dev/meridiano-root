# Meridiano — Fase 3.4 ∥ 3.5 — Contrato de dependência e Task 0

> **Para agentes:** este documento é a condição (b) do plano-mestre ("Paralelismo"): 3.4 (`2026-09-09-fase-3-4-cadastros.md`) e 3.5 (`2026-09-09-fase-3-5-financeiro.md`) só correm em paralelo depois que a **Task 0** abaixo estiver commitada nos dois repos. Cada subplano é um plano completo próprio; este arquivo define o que é compartilhado, quem é dono de cada arquivo, e a única task que toca os arquivos comuns.

**Estado de partida:** 3.3 mergeada em `main` (backend `9edb433`, frontend `f488107`), migrations 0001–0014, 179 testes API + 22 domínio, 237 Vitest + Playwright 8/8.

## 1. Regras de execução conjunta

1. **Branch única por repo:** `feat/fase-3-4-3-5` em `backend/` e em `frontend/`. Commits por task com escopo Conventional Commits distinto (`feat(pessoas)`, `feat(grupos)`, `feat(fornecedores)` para 3.4; `feat(financeiro)`, `feat(repasses)`, `feat(despesas)`, `feat(fechamento)` para 3.5). Um merge em `main` no fim, depois das duas tasks de fechamento. Root (`meridiano-root`) só docs.
2. **Task 0 primeiro, serial.** Nenhuma task de 3.4 ou 3.5 começa antes do commit de T0 nos dois repos.
3. **Ondas independentes por subplano.** O controlador pode rodar a onda N de 3.4 ao mesmo tempo que a onda M de 3.5. Teto: **6 implementadores simultâneos**, no máximo **4 no backend** ao mesmo tempo (a solution compila inteira; mais que isso multiplica corrida de build).
4. **Propriedade de arquivo é exclusiva** (tabela §3). Task que precisar tocar arquivo do outro subplano **para** e reporta ao controlador, que reescala a task para depois (ou renegocia o contrato). Nunca editar arquivo alheio "só um pouco".
5. **Arquivos congelados** (§4) não são editados por nenhum dos dois subplanos. Necessidade real → item no BACKLOG + decisão do controlador.
6. **Build compartilhado.** Implementador escreve arquivo inteiro (nunca meio arquivo salvo); se `dotnet build`/`tsc` falhar num arquivo que não é dele, espera 60 s e tenta de novo (até 3×), depois reporta — não corrige código alheio. `dotnet test --filter` nos próprios testes durante a task; suíte completa (`dotnet test`, `npm run test`) só no fim da task.
7. **Commit por task pelo controlador**, com pathspec explícito dos arquivos que a task reportou (nunca `git add -A`), depois que a suíte completa do repo estiver verde. Se a suíte estiver vermelha por task **em andamento** do outro subplano, o controlador espera essa task fechar, não commita em cima.
8. **Fechamento (docs no root) é serial:** a task de fechamento de cada subplano (`BACKLOG.md`, `autorizacao-por-operacao.md`, plano-mestre, `CLAUDE.md`) roda uma depois da outra, nunca na mesma onda. Ordem: quem terminar primeiro.
9. **Reviewers** por task como no `.claude/rules/parallel-subagent-driven-development.md` (só leitura; escopo = commit range da task).

    if (m is { Length: > 500 }) m = m[..500];
    return new ContextoSessao(u.AgenciaId, u.UsuarioId, string.IsNullOrWhiteSpace(m) ? null : m);
}
